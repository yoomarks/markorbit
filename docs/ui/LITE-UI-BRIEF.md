# MarkOrbit Lite UI Brief

**Users/job:** trademark agents, IP and brand-service professionals, and small professional teams need to prioritize multi-customer work, evidence, opportunities, and governed next actions.

**IA:** fixed primary navigation is Today, Content, Opportunities, Trademarks, Work, Capability, Guide. Guide is workflow assistance, never generic chat. Today groups pending attention, opportunities, trademark status, work, and Capability suggestions.

**Behavior:** desktop uses a persistent rail and dense three-column summaries; mobile stacks summaries and provides scrollable navigation without losing labels. Initial/loading/empty/partial/ready/stale/warning/recoverable and blocking error/offline/unauthorized/forbidden/not-found follow the shared model. Permission and stale states prevent protected actions. Fixture content remains visibly marked.

**Accessibility/acceptance:** landmarks, current-page semantics, headings, visible focus, text status, reduced motion, and responsive reflow. Fixture-backed Storybook covers desktop and small screen. Playwright acceptance path for the next journey task: open Today → traverse seven navigation items by keyboard → inspect pending attention → verify fixture warning; this foundation does not add Playwright infrastructure.

**Customers runnable preview:** `customers-preview.html` exposes the existing fixture-only Customers list and detail hierarchy for deterministic desktop and mobile review. Query scenarios cover ready, loading, empty, stale and recoverable error states; the incomplete long-form fixture proves partial-data wrapping and unavailable context. The preview does not establish a Customer owner, legal identity, relationship, authority or instruction truth and is not a production navigation cutover.

**Content Studio runnable preview:** `content-studio-preview.html` exposes the Product-owned Content Studio list/detail hierarchy, exact lineage and governed preparation controls with deterministic in-memory fixtures. Query scenarios cover ready, loading, empty, partial, unauthorized, permission-denied and recoverable owner-error states; `view=detail` opens the exact fixture work directly. Review, PublishPackage preparation and user-feedback progression remain inside the browser session and do not publish externally, spend money, establish Official Truth or change production owner data. This entry is not a production navigation or authentication cutover.

**Today Workspace runnable preview:** `today-workspace-preview.html` exposes the existing Daily Workspace hierarchy as MOVE → SEE → CREATE, with Today Actions, ranked Orbit evidence, Content Picks and Quick Create in one deterministic fixture surface. Query scenarios cover ready, loading, empty, partial, unauthorized, permission-denied and recoverable owner-error states. Explicit confirmation can complete only the bounded Lite owner handoff; preference events and reuse-first Visual Brief preparation stay in browser memory and do not publish, authorize paid/provider execution, establish Official Truth or change production owner data. Desktop and 390px mobile preserve the same semantic order. This entry is not a production navigation or authentication cutover.

**Opportunity Center runnable preview:** `opportunity-center-preview.html` exposes the Product-owned Candidate Review hierarchy as Candidate list → exact Candidate and source evidence → human Qualification. Query scenarios cover ready, loading, empty, partial pagination, unauthorized, permission-denied, detail dependency failure, recoverable owner error and Qualification conflict. Successful fixture decisions reload browser-memory owner truth; conflicts preserve the reviewed evidence and entered rationale. Qualification does not contact a customer, create a Formal Opportunity, Intake, Order, Matter, Payment or Filing, authorize payment/filing, or establish Official Truth. Desktop and 390px mobile preserve the same evidence-before-action order. This entry is not a production navigation or authentication cutover.
